# Runtime notes

- The skin discovers the current `OpenAI.Codex` package on every run and requires a non-development `Store` signature kind. It prefers manifest-derived AUMID package activation with explicit `--remote-debugging-address=127.0.0.1`, the selected port, and a persistent non-default `%LOCALAPPDATA%\CodexDreamSkin\cdp-profile`. Chromium 136+ requires that isolated data directory before it honors remote-debugging switches; `-ProfilePath` remains an explicit advanced override. Only when a visible command line proves that owl encoded the debugging argument inside `codex://` does it preserve the pre-launch PID set, stop newly observed package processes, and make one direct raw-argument attempt against the exact validated `app\ChatGPT.exe`. An absent flag without that protocol evidence stays on the conservative package-activation path. Access denial or a second argument-forwarding failure is terminal; the caller rolls back to normal package activation without debugging flags.
- Node.js 22 or newer is required for the built-in WebSocket client. The runtime's real `process.execPath` and version are recorded in state, even when PATH points at a shim.
- The preferred port is `9335`; the default launcher scans up to 100 ports when it is occupied. An explicit occupied port is rejected.
- CDP is accepted only when its listener PID resolves to the exact Store `ChatGPT.exe`, every WebSocket URL is loopback and same-port, `/json/version` exposes a valid Browser ID, and the renderer has expected Codex shell markers.
- Loopback prevents access from the LAN, but CDP does not authenticate other processes running as the same Windows user. Treat the themed session as a local debugging session, run only trusted local software, and restore when it is no longer needed.
- The injector keeps the original Browser WebSocket open as an identity anchor. It reinjects after renderer loads while that anchor remains alive, but exits instead of attaching when the browser closes or the port is reused. Target failures use capped exponential backoff and rate-limited logging.
- `%LOCALAPPDATA%\CodexDreamSkin\state.json` records the Browser ID, registered Appx full/family names, port, injector and Node paths, PID, and process start time. Schema 3 cleanup requires all recorded process identity fields to match. Legacy state lacks some fields and is stopped only when the PID still exposes `node.exe`, the exact injector script, watch mode, and saved port; otherwise the state is moved to `state.stale-*.json` without stopping the process.
- If Codex is already running without the chosen debugging port, the shortcut asks before restart; CLI callers must close it or explicitly pass `-RestartExisting`.
- Restore does not require Node to remain installed: it preflights config backups, closes Codex to clear live DOM and CDP, stops only the verified recorded injector, applies requested config changes, then reopens the official app without debug flags.
- A live recorded injector whose PID no longer matches the saved Node path, injector command line, port, Browser ID, or start time causes start/restore to abort with state preserved; it is never silently archived and replaced.
- The managed theme root rejects junctions and symbolic links before initialization, import, save, switch, pause, or state writes. Windows uses the bundled Node image-metadata helper to enforce the same 10 MB, 16384px, and 50MP limits before an import is copied.
- `config.toml` is read from raw bytes as strict UTF-8, written without BOM through same-directory atomic replacement, and backed up byte-for-byte. Install requires Codex to be closed; writes stage the temporary file first, then abort if the destination bytes changed immediately before replacement. Quoted keys and table-header comments are supported; escaped target keys, multiline strings/arrays, dotted target keys, or duplicate target keys fail before writing. Before marker/config commits, startup persists a strict 64 KiB `preparing` transaction containing only the managed key and marker snapshots. Caught failure or the next locked operation after a hard process stop restores each key only when its current exact line still equals the attempt's applied value, recognizes already-restored values, preserves newer/unrelated edits, and commits ownership metadata last. Recovery is blocked when the attempt's Codex processes cannot be confirmed closed. Completed restore backups are retained as `config.restored-*.toml` so reinstall captures a fresh baseline.
- A per-user named mutex prevents concurrent install, start, restore, and verify operations from racing state, ports, or config writes.
- The installer compares every staged runtime file with its selected source by SHA-256, then clears Internet-zone markers only from staged managed `.ps1` copies. Installed shortcuts and tray child processes use process-scoped `RemoteSigned`; Machine/User Policy remains authoritative and no persistent execution policy is changed.
- Store updates are supported because the launcher queries `Get-AppxPackage OpenAI.Codex` on every launch. State paths are eligible for automatic cleanup only after their Appx full name, family name, install root, and executable are matched against a currently registered package; an active unverified old path requires manual closure.
- Store `26.715.10079.0` introduced an owl activation path that can encode `--remote-debugging-port` under `codex://...path=`. The manifest exposes no app-execution alias, so the bounded exact-executable fallback is the only non-mutating diagnostic. Field evidence in issue #235 confirms both terminal outcomes: direct execution is blocked by the WindowsApps ACL on `26.715.10079.0`, and `26.721.3404.0` retains the raw flags but exposes no listener. Neither can be bypassed within this project's safety boundary. Never grant new WindowsApps permissions, take ownership, copy the binary out of its package, or patch the package to bypass a failed fallback.

## ZCode Dream Skin runtime notes

- 目标应用：`ZCode.exe`（`F:\AI\ZCode\ZCode.exe` 为已验证样例），Authenticode `Valid`、主体含「北京智谱华章科技股份有限公司」、ProductName `ZCode`；版本 `3.14.4.7912`，DOM 指纹 `ddc4dee432144a1c6974df23d6e1392e`。
- ZCode 是整机级单实例：需要 CDP 的运行必须先由用户正常退出 ZCode；本产品只管理自己启动的进程树，绝不结束未知 PID。
- 状态根：`%LOCALAPPDATA%\ZCodeDreamSkin\`（`state.json` schema `zcode-dream-skin-state/1`；`installer.json` 记录安装时验证的 ZCode 路径与 SHA-256）。
- 完整恢复：暂停只实时移除主题（ZCode 保持运行）；完整恢复优雅关闭受管会话、清理状态并正常重启 ZCode。
- 端口：默认从 9335 自动搜索；显式端口被占报 `E05_CDP_PORT_FOREIGN_OWNER` 且从不结束占用者；搜索耗尽报 `E12_CDP_PORT_SEARCH_EXHAUSTED`。
- 错误码表：见 `windows/scripts/zcode-product.ps1` 的 `Get-ZCodeDreamSkinErrorCodes`（E01–E14）；日志标签 `[LAUNCH]…[ERROR]` 单行化，不含用户内容。
- 证据审计：`.lemon/evidence/zcode-dom-inventory.json` 由 `zcode-inventory-audit.mjs` 复核（退出码、清理、就绪、泄漏值、指纹一致性）后才可采信。
- 一次性现场验收：`windows/scripts/zcode-live-acceptance.ps1`（ZCode 全部退出后运行；0=通过、2=失败、3=被阻塞）。
- 启动等待：`injector.mjs` 的产品连接不再对 `/json/list` 只读一次，而是按截止时间轮询等待唯一主 renderer（`--startup-timeout-ms`，默认 120000ms、间隔 500ms）；只重试 `E07_NO_RENDERER_TARGET`，`E08_TARGET_AMBIGUOUS` 与 browser id 变化立即失败。拿到 session 后还要等工作区水合（body 元素数达标、有 workspace 证据、无启动标记、连续稳定采样），未就绪返回 `E11_WORKSPACE_NOT_READY`，绝不把主题注入启动页。CDP 页表只接受 `zcode:`/`app:`/`file:` 本地应用 scheme（ZCode 实测为 `file://…/index.html`）。
- 启动事务：`<StateRoot>\launch-transaction.json` 记录「这次启动发生过、可能需要回滚」，阶段为 `launch-requested → launched → cdp-ready → renderer-ready → theme-applied → active`（回滚期 `rolling-back → rolled-back|rollback-failed`）。它在启动前落盘、在 active state 接管会话后才清除；失败时保留事务与诊断，下次启动只报告未决事务并另存为 `launch-transaction.superseded-<时间戳>.json`，绝不猜测关闭其它 ZCode。
- 启动报告与残留诊断：每次启动（成功或失败）都写 `<StateRoot>\last-startup-report.json`，含 `phase`、`fileVersion`、`launchedPid`、`browserId`、`primaryError`、`rollback`（attempted/complete/residualPids/portListenerOwners）与 `transactionKept`；验收报告另有 `launchRecovery`（事务是否存在、rollback 结论、实测残留 pid 与端口属主、是否 recovered）。回滚只关闭事务能证明属于本次启动的进程（核对路径、创建时间、启动前 PID 集合、端口归属），成功与否用实测进程与端口判定，不采信单条命令的 exit code。
- 状态根取决于启动环境：从 ZCode 自带终端运行时 `$env:LOCALAPPDATA` 指向该应用的包内重定向目录（`…\Packages\<包>\LocalCache\Local`），状态、事务与报告都落在那边；从资源管理器或托盘启动时才是 `%LOCALAPPDATA%\ZCodeDreamSkin`。两者互不读取，排查时以日志与报告里实际出现的路径为准。
- 主题应用契约：`zcode-renderer-inject.js` 是**注册型** payload——执行它只安装 `window.__ZCODE_DREAM_SKIN__` 并返回 `undefined`，不会建任何节点。因此「注册 payload 的返回值」不能当作应用结果；一次性 apply 与 watcher 的 reload 重注入都走同一个 `registerAndApplyZCodeTheme(session, payload, expectedMode)`：先跑真实 payload，再在同一 session 执行显式表达式检查 runtime/apply 并调用 `api.apply()`，最后跑独立 DOM 验证。失败统一 `E09_RUNTIME_EVALUATE_FAILED`，报告以 `failureStage=register|apply|verify` 区分阶段并引用实测字段（`applied`/`mode`/`reason`）；三段中任一不通过，`applied` 都不会为 true，CLI 退出码非零。full 要求三个固定节点各恰好 1 个、背景与 overlay `pointer-events:none`、`data-zcode-dream-skin` 与预期 mode 一致且注册表面已标记；safe 额外要求零 full 部件；deny 只注册、绝不进入 apply。暂停时的拒绝会被保留，绝不清 pause lock 来制造成功。
- 启动成功判据：启动器在 apply 前先删除旧的 `last-apply-report.json`，apply 后要求该文件存在、属于本次 launch（`mode`/显式布尔 `applied`/空 `failureStage`/无 `errors`/`full|safe`/`port`/`browserId`/三节点各 1/`pointer-events` 为 none/`verify.mode` 与 `compatibilityMode` 一致）。任何一条不满足即 `E09`，走既有启动事务回滚：不写 active state、不启动 watcher。exit code 与文件存在都不构成证据。
- watcher 生命周期：watcher 必须能按 state 文件的 `stopped` 标志退出——它在 `finally` 中先 `lifecycle.stop()` 再释放自己唯一持有的 CDP session，否则未关闭的 socket 会吊住 Node 事件循环，停止请求只会被打印而永不生效，产品只能退化成按超时处理自己的子进程。重新发现（renderer reload 之后）会先释放上一条连接，避免长跑 watcher 累积 socket。`paused` 状态的 watcher 逻辑上结束本轮循环。恢复由 `restore -Mode Resume` 解锁 renderer 后委托独立的 `start-zcode-dream-skin.ps1 -StateRoot ...` 重新应用：沿用当前可执行版本、活动库输入、新鲜报告校验和监控重建，不再单独拼一组缺版本参数的 `zcode-apply` flags。解锁或重应用失败都返回非零，不用旧verify报告宣布成功。
- 状态布尔字段与旧 state：`New-ZCodeDreamSkinState` 显式声明 `paused` 与 `stopped`。`ConvertFrom-ZCodeDreamSkinStateJson` 对旧 schema/1 里**缺失**的这两个字段补默认 `false`，已有值原样保留，**不改写任何身份字段**（rootPid/port/browserWebSocketUrl/watchPid/已验证路径/指纹），因此身份校验不会因迁移而放宽；出现非布尔值（含字符串 `"false"`）一律 `E13_STATE_SCHEMA_INVALID`，不用 PowerShell 隐式转换。恢复路径写标志一律经 `Set-ZCodeDreamSkinPaused` / `Set-ZCodeDreamSkinStopped`（字段缺失时 Add-Member 后再赋值），不再直接向 JSON 读回对象赋值——那正是 `The property 'stopped' cannot be found` 中止完整恢复的根因。
- watcher 身份与 stale state：录制 PID 存在不等于 watcher 存在（PID 会被复用）。停止前必须同时满足：进程可执行文件是 `node.exe`、命令行含**精确**的 injector 脚本路径、`zcode-watch` 模式、以及**精确**的 state 文件路径；任一项不符只报告、绝不结束该进程，且 stop 请求一旦发出不回收，避免已停止 watcher 复活重注入。完整恢复的成功以实测为准：受管进程树**与**调试端口都排空后才清 state 并正常重启；未排空则保留 state 与残留报告（`E06`）。遗留 state 只在录制的 root、watch 与端口**全部释放**时才归档为同目录 `state.stale-<时间戳>.json`（保留全部身份字段作为证据，不删除）；root PID 被别的可执行文件复用、watcher 仍在、或端口有未知属主时一律拒绝，state 原地不动。
